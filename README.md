# Price Lantern

A small, local-first price tracker. **A browser extension with a full-tab watchlist** is the first product: people can add a price where they already shop, without signing up or copying everything into another app.

The recommendation is a product hypothesis, not an adoption statistic. A mobile share sheet or a cloud monitoring service could follow if demand warrants it. This MVP targets Chrome, Edge, and Firefox on desktop; Safari has not been tested.

## Try it

1. Open `chrome://extensions` (or `edge://extensions`).
2. Enable **Developer mode**.
3. Choose **Load unpacked** and select this `still-price-tracker` folder.
4. Pin **Price Lantern**. Visit a product, click Price Lantern, and choose **Track this page**.
5. Confirm the product and currency, set an optional target, and save. Grant access only to the shop you want to track.

For Firefox 142 or newer, open `about:debugging#/runtime/this-firefox`, choose **Load Temporary Add-on**, and select `manifest.json` from this folder. Temporary add-ons are removed when Firefox exits. A permanent Firefox installation requires a signed add-on. Existing watchlists keep their data when upgrading the extension in place.

If automatic detection cannot find one unambiguous price, use **Pick a price on the page**. Hover over the exact price and click; press Escape to cancel. Select the product variant you actually want before picking. Prices inside cross-origin frames and closed shadow roots are not supported.

For a visual preview without installing anything:

```sh
cd still-price-tracker
npm run serve
```

Open http://127.0.0.1:4173. The preview is clearly marked and uses illustrative sample prices. Add/edit/filter/settings/export work locally; live checks require the extension. The extension itself starts empty.

## Customize a source

Each item supports:

- **Automatic detection (default):** a matching shop rule from the public [source catalog](sources.json) when available; otherwise a single Product/Offer price in JSON-LD, Open Graph price metadata, or a single microdata price element. Multiple offers are deliberately rejected rather than guessing a variant.
- **Page element:** an exact CSS selector, entered manually or generated by the price picker. Exactly one matching element is required. Select only the current price, not a container with old prices, percentages, or payment instalments.
- **JSON API:** a public GET endpoint and a dot-separated path such as `0.price.amount`. Arrays use numeric indexes. It never executes supplied JavaScript. API requests omit cookies and reject redirects; authenticated APIs are not supported.

Set the currency and decimal format when detection is ambiguous. Currency labels must be confirmed by the user; `$` alone cannot distinguish USD/CAD/AUD. Separate currencies and product URLs require separate watches to keep history meaningful.

### Shared source catalog

The [catalog](sources.json) is public in this repository. Price Lantern checks its [published copy](https://raw.githubusercontent.com/msmece/still-price-tracker/main/sources.json) at most once per 24 hours, caches valid rules locally, and uses bundled rules if it cannot reach GitHub. The request only fetches the shared rule list; it does not send your product URLs or history to GitHub. A new rule can be proposed through a pull request to this repo. A rule has a `type` (`selector` or `json-api`), shop `host`, exact `selector`, and three-letter `currency`. Selector rules may use an optional `attribute` (`content` or `data-*`); otherwise they read text. JSON API rules read product JSON from a `data-*` attribute using `idPath`, `namePath`, and `pricePath`, then check the shop's HTTPS `apiPrefix` and `apiPath`. A rule must identify exactly one price. Rules cannot execute downloaded JavaScript or redirect API requests to another host. If a rule is missing or outdated, manual selectors and API sources still work. A rule must be tested against a real product page before merging; it cannot guarantee coverage of every shop or variant.

### JYSK example

VIRUM's current price can be tracked even when JYSK doesn't publish a lowest-30-day reference price:

```text
Product: https://jysk.de/esszimmer/vitrinen/vitrine-virum-hoch-2-tueren-sand
API:     https://jysk.de/service/search/product-teaser-lookup?locale=de-DE&ids=3620281
Path:    0.price.unformatted.minSingle
Currency: EUR
```

Adding a JYSK Germany page through **Track this page** automatically configures this API when the page supplies its article number. The adapter reads current prices, not the retailer's historical discount label. The endpoint is internal and may change.

## What runs, and when

- Zero runtime dependencies, no bundler, account, server, analytics, remote fonts, or image requests. Only the shared catalog is fetched from GitHub once a day (or on the next capture when offline).
- State lives in extension local storage. Preview state lives separately in browser localStorage.
- Checks default to every six hours. Choose hourly, six-hourly, twelve-hourly, daily, or manual.
- A lightweight alarm wakes once a minute, checks at most one due item, and serializes network checks. Browsers can delay alarms; the browser must be running. This is not an always-on service.
- API watches make a direct request. Page watches briefly open a real **inactive tab**, wait for the rendered price, then close it. This supports client-rendered pages, but the site's scripts still run. Login walls, bot challenges, lazy-loaded elements, changing selectors, and personalized prices can prevent or alter readings. Errors are shown without replacing the last valid price.
- Up to 50 watches and 2,000 observations per watch. Charts show the latest 60 observations. “Lowest observed · last 30 days” uses only the observations actually collected in that window; it is not a guaranteed daily minimum or the retailer's statutory reference price.
- Target alerts are optional and fire on crossing from above to at/below the target. Operating-system and browser notification settings also apply.
- Export saves your watchlist, settings, and observations as JSON. Removing an item deletes its saved history.

“All websites” is a customization goal, not a guarantee. Shops must expose a readable price or an accessible API. This MVP does not bypass access controls or bot protection.

## Permissions

Required: `activeTab`, `scripting`, `storage`, `alarms`, and access to `raw.githubusercontent.com` to fetch the public source catalog. Persistent shop access is requested per origin when saving/testing an item. Notification permission is requested only when enabling alerts. No browsing-history, cookie, or blanket install-time shop permission is required. Manage/revoke grants through your browser's extension settings.

Browser references: [optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions), [alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms), [script injection](https://developer.chrome.com/docs/extensions/reference/api/scripting), [Firefox background scripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background).

## Verify

```sh
cd still-price-tracker
npm test
```

Tests cover localized number parsing, unsafe URLs/JSON paths, source validation and rule fallbacks, target crossing, observed-history windows, startup without notification access, concurrent writes, and preserving history on failed checks/edits.

The dashboard is native HTML/CSS/ES modules. Extension behavior is in `background.js`; page extraction and the picker in `capture.js`; validation and price/history rules in `model.js`.

Run `npm run package` to build separate ZIP files for Chrome and Firefox. Upload the `-firefox.zip` archive to Firefox Add-ons; its manifest contains only the Firefox background script. The Chrome archive contains only the service worker. Firefox store distribution requires Mozilla signing. Manual approval of native permission prompts and OS notification delivery should be checked in a normal browser before publication.
